Class & Object

A class is a blueprint (like a product template in an e‑commerce app). Objects are the real items built from it.

class Product:
    def __init__(self, name, price):
        self.name = name      # attribute
        self.price = price
    def label(self):         # method
        return f"{self.name}: ₹{self.price}"

p1 = Product("Phone", 19999)
p2 = Product("Mouse", 599)
Same class, different data, each object has its own identity.

Constructor & Destructor

__init__ runs when an object is created; __del__ runs just before it’s destroyed (when no references remain).

class DBConnection:
    def __init__(self, url):
        self.url = url
        print("connecting…")
    def __del__(self):
        print("closing connection")

conn = DBConnection("shop.db")
del conn   # refcount → 0
no object
Tip: prefer context managers for cleanup, as __del__ timing isn’t guaranteed.

Pillar 1 · Encapsulation

Hide internal state; expose a safe interface. Python uses _name (convention) and __name (name mangling).

class BankAccount:
    def __init__(self):
        self.__balance = 1000
    def withdraw(self, amt):
        if amt > self.__balance:
            raise ValueError("Insufficient")
        self.__balance -= amt
    @property
    def balance(self):
        return self.__balance

Pillar 3 · Polymorphism

Same method name, different behaviour. The caller doesn’t care which concrete class it’s talking to.

class Card:  def pay(self, a): return "Charged card"

Pillar 4 · Abstraction

Define what must be done, not how. Abstract base classes (ABC) force subclasses to implement the contract.

from abc import ABC, abstractmethod

class Payment(ABC):
    @abstractmethod
    def pay(self, amount): ...

class Razorpay(Payment):
    pass              # forgot pay()
class UPI(Payment):
    def pay(self, amount): ...

Dunder (Magic) Methods
Double‑underscore methods let your objects work with Python’s syntax and built‑ins. Click an expression to see which dunder it triggers.


class Money:
    def __init__(s, v): s.v = v
    def __add__(s, o): return Money(s.v + o.v)
    def __eq__(s, o):  return s.v == o.v
    def __lt__(s, o):  return s.v < o.v
    def __str__(s):   return f"₹{s.v}"
    def __repr__(s):  return f"Money({s.v})"
    def __len__(s):   return 2   # items

a, b = Money(500), Money(250)

Iterators
An iterator implements __iter__ and __next__. A for loop just calls next() until StopIteration.


class Cart:
    def __init__(s, items): s.items = items
    def __iter__(s):
        s.i = 0; return s
    def __next__(s):
        if s.i == len(s.items):
            raise StopIteration
        s.i += 1
        return s.items[s.i - 1]

it = iter(Cart(["Phone","Case","Cable"]))


Generators (yield) build iterators with far less code.



Context Managers
The with statement guarantees setup and cleanup via __enter__ / __exit__, even when errors happen.


class FileSession:
    def __enter__(self):
        print("open file"); return self
    def __exit__(self, et, ev, tb):
        print("close file")
        return False   # don’t swallow errors

with FileSession() as f:
    process(f)


Also available: @contextmanager from contextlib.
